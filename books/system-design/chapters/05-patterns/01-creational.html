Creational patterns: how objects get made

Creational patterns control object creation so that code isn't littered with new and complicated construction logic.

Singleton: exactly one instance

At Ramu's chai stall

There is one master cash register for the whole shop. If every cashier bought their own register, the day's totals would never add up. Everyone uses the register.

Intent: ensure a class has only one instance and provide a global access point. Use for: configuration, a connection pool, a registry, a logger. Real world: Runtime.getRuntime(); Spring beans are singletons per container by default.

Common trap

Singletons are global state in disguise: they hide dependencies and make tests share state. In Spring apps, let the container manage a single bean and inject it instead of calling getInstance() everywhere.

Factory (Simple Factory and Factory Method): hide which class gets built

At Ramu's chai stall

A customer says "One lemon tea." They don't go into the kitchen and pick a machine. The counter (the factory) decides which machine makes it and hands over the cup.

Intent: create objects without the caller knowing the concrete class. Factory Method (GoF) lets subclasses decide which class to instantiate; the everyday simple factory is one method with the decision inside. Real world: Calendar.getInstance(), NumberFormat.getInstance(), Spring BeanFactory.

Abstract Factory: families of things that belong together

Intent: create families of related objects without naming their concrete classes, so the pieces always match. The Kolkata branch kit gives a clay kulhad cup and a samosa; the Mumbai kit gives a glass cutting-chai cup and vada pav. You never mix a kulhad with vada pav.

Builder: construct complex objects step by step

At Ramu's chai stall

A catering order has 15 options: cups, flavour, sugar level, milk type, delivery time, address, cups or flasks, invoice name… Shouting them all in one breath in a fixed order is a recipe for mistakes. A form you fill field by field, then submit, is a builder.

Prototype: copy a ready-made object

Intent: create new objects by copying an existing, configured one instead of building from scratch. Ramu keeps a "standard wedding package" template; for each new wedding he copies it and changes the date and address.

Lock it in

"Sita Found A Big Present": Singleton, Factory, Abstract factory, Builder, Prototype.

Singleton = one. Factory = which one. Abstract factory = matching set. Builder = many options, step by step. Prototype = copy and tweak.

Interview questions

How can a singleton be broken, and how does an enum prevent it?

Reflection can call the private constructor; serialization/deserialization creates a new instance (unless readResolve is defined); cloning can copy it; and multiple class loaders each get their own. Enums are protected by the JVM: their constructors can't be invoked reflectively and serialization returns the same constant.

Factory Method vs Abstract Factory?

Factory Method creates one product, and subclasses decide its class by overriding a method (inheritance). Abstract Factory creates a family of related products through an object you pass in (composition). An abstract factory is often implemented with several factory methods.
