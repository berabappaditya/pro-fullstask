Behavioral patterns: how objects cooperate

Behavioral patterns are about responsibilities and communication: who decides, who gets told, and how work passes along.

Strategy: swap the algorithm

At Ramu's chai stall

Delivery charges change with the situation: normal days ₹20, rainy days surge pricing, festival days free over ₹200. The delivery desk keeps a card for each pricing rule and simply picks today's card.

Observer: tell everyone who cares

At Ramu's chai stall

When a fresh batch of samosas comes out, Ramu rings a bell. Whoever is waiting (customers, the delivery desk, the stock clerk) reacts in their own way. Ramu doesn't need to know who's listening.

Command: turn a request into an object

An order slip is a request written down: it can be queued, logged, retried, or cancelled (undone). The Command pattern does the same in code.

State: behaviour changes with state

Template Method: fixed steps, customisable details

You met this in {{ref:ch-oop}}: Chai.prepare() is final and fixes the order of steps; subclasses fill in addExtras(). Real world: Spring's JdbcTemplate, RestTemplate, AbstractController; JUnit's setUp/test/tearDown lifecycle; HttpServlet.service() calling doGet()/doPost().

Chain of Responsibility: pass it along until someone handles it

At Ramu's chai stall

Refunds: the cashier can approve up to ₹100, the branch manager up to ₹1,000, anything bigger goes to Ramu. A request walks up the chain until someone has the authority.

Four more to recognise

Iterator
Walk a collection without exposing its insides

Iterator<T>, the for-each loop. Lists, sets and trees all iterate the same way.

Mediator
A central hub so objects don't talk directly

An airport control tower; a chat room routing messages between users. Cuts many-to-many links to one-to-many.

Memento
Save and restore an object's state

"Undo" in an editor; saving a game checkpoint, without exposing internals.

Visitor
Add operations to a class hierarchy without editing it

Tax calculation and export over a tree of menu items; compilers walking syntax trees.

Strategy swaps HOW. State swaps WHO-I-AM. Observer shouts WHAT-HAPPENED.

Command = request as an object (queue, undo). Template = fixed recipe, custom steps. Chain = pass it up until someone handles it.

Interview questions

Strategy vs State: they look identical. What's the difference?

Structurally both delegate to an interface. In Strategy, the client picks the algorithm and strategies don't know about each other. In State, the state objects themselves trigger transitions to the next state, and the set of allowed operations changes as the object moves through its lifecycle.

What's the downside of the Observer pattern?

Flow becomes implicit: reading the publisher doesn't tell you what happens next. Listener order may be undefined, a slow or failing listener can affect the publisher if run synchronously, and forgotten subscriptions leak memory. Use clear event names, async listeners for slow work, and tracing.
