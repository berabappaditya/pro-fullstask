Liskov Substitution Principle

If B is a subtype of A, you must be able to use a B anywhere an A is expected, without surprises. A child class must keep its parent's promises.

At Ramu's chai stall

Ramu's delivery boy Raju falls sick, and the agency sends a replacement: "He's a delivery boy too." Ramu hands him 20 orders and the scooter keys. Turns out the replacement can't ride a scooter; he only walks. Every delivery is 40 minutes late. On paper he is a delivery boy, but he can't be substituted for one, because he breaks the promise everyone relied on: "deliveries arrive within 15 minutes".

Definition

Barbara Liskov (1987): objects of a superclass should be replaceable with objects of its subclasses without altering the correctness of the program. In practice a subclass must not:

  • Demand more (stronger preconditions): parent accepts any amount, child rejects amounts over ₹100.
  • Promise less (weaker postconditions): parent always returns a receipt, child sometimes returns null.
  • Break invariants: rules that must always hold for the parent (balance ≥ 0).
  • Throw new surprises: UnsupportedOperationException for an inherited method.

The famous one: is a Square a Rectangle?

Signs you're breaking LSP

Empty or throwing overrides

throw new UnsupportedOperationException() in a subclass.

instanceof checks

Callers test the concrete type before calling a parent method.

"Is-a" in English only

Penguin is a bird, but Bird.fly() doesn't fit it.

Even the JDK bends this rule: List.of(…) and Collections.unmodifiableList(…) are Lists whose add() throws UnsupportedOperationException. A good interview talking point.

Lock it in

If it looks like a duck but needs batteries, it's the wrong abstraction.

A subtype must accept at least as much, deliver at least as much, and never surprise. Inheritance means "behaves like", not just "is called".

Interview questions

How is LSP related to OCP?

OCP relies on swapping implementations behind an abstraction. That only works if every implementation honours the abstraction's contract, which is exactly what LSP guarantees. An LSP violation forces instanceof checks into the calling code, which then has to be modified for each new subtype, breaking OCP.

How would you fix Bird / Penguin?

Remove fly() from Bird. Keep common behaviour (eat(), layEggs()) in Bird, and add a Flyable interface implemented only by birds that fly. Code that needs flying takes Flyable.
