Open/Closed Principle

Software should be open for extension but closed for modification. Add new behaviour by adding new code, not by editing code that already works.

At Ramu's chai stall

Ramu's first menu was painted directly on the wall. Every time he added a drink (cold coffee in summer, kadha in winter) a painter had to repaint the wall, and twice he smudged existing prices. So Ramu switched to a board with slots: each item is a card that slides in. The board itself never changes; it's closed. But it's open: any number of new cards can be added.

Definition

A module should allow its behaviour to be extended without changing its source code. In Java you achieve it with abstractions (interfaces / abstract classes) plus polymorphism: the stable code depends on the interface, and new behaviour arrives as new implementations.

Interview tip

OCP is what the Strategy, Decorator, Template Method and Observer patterns are for. When you see a growing switch or if-else on a type, say: "I'd replace this conditional with polymorphism so new types are additions, not edits."

Common trap

Making everything pluggable "just in case". OCP is applied where change is likely (pricing rules, payment methods, notification channels). Abstracting things that never vary adds indirection for nothing (see YAGNI, {{ref:ch-beyond}}).

Lock it in

Slide in a new card; don't repaint the wall.

Stable code depends on an interface; new behaviour = new class. A growing switch on type is the classic OCP smell.

Interview questions

Where does the JDK or Spring itself follow OCP?

Collections.sort(list, comparator): the sort algorithm is closed, and you extend the ordering with any Comparator. In Spring: add a HandlerInterceptor, a Filter, a new @Bean implementing an interface, or a BeanPostProcessor, and the framework picks it up without its code changing.

Is it ever OK to modify existing code?

Of course: to fix bugs, and to refactor towards an abstraction the first time a second variant appears ("rule of three"). OCP is a goal for the parts of the system that change for predictable reasons, not a ban on editing.
