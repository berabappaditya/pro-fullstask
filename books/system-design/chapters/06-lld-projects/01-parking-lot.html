LLD project: a parking lot

The most common LLD interview question, solved with the framework, a class diagram and working, thread-safe Java that uses the principles and patterns from this book.

The LLD interview framework

  1. Clarify requirements (5 min)What must it do? What's out of scope? Ask about scale, concurrency and which parts may change in future.
  2. Find the entities (5 min)Underline the nouns in the requirements: they become classes. Verbs become methods.
  3. Draw the class diagram (10 min)Classes, key fields and methods, relationships and multiplicities. Mark interfaces where things vary.
  4. Pick patterns where they fit (in passing)Strategy for rules that vary, State for lifecycles, Observer for notifications, Factory for creation. Say why.
  5. Write the core code (20 min)The main flows end to end, clean names, SOLID. Skip boilerplate (getters, imports).
  6. Discuss concurrency, edge cases, extensions (5 min)Two cars, one spot. Lost tickets. A new vehicle type. Show that adding it is an addition, not a rewrite.

Step 1 · Requirements

Must have
  • Several floors, each with spots of sizes SMALL, MEDIUM, LARGE
  • Bikes, cars, trucks; a vehicle may use a bigger spot if its size is full
  • Entry: assign a spot, issue a ticket
  • Exit: compute fee by duration and vehicle type, take payment, free the spot
  • Show free spots per floor
Design goals
  • Two entry gates must never assign the same spot
  • Pricing rules and allocation rules will change (weekend rates, EV-first floors)
  • Easy to add a vehicle type (EV, bus)
  • Out of scope: reservations, licence plate cameras
