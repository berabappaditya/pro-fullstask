APIs: REST, GraphQL, gRPC and real-time

An API is the contract between two pieces of software: what you can ask for, how to ask, and what you'll get back.

At Ramu's chai stall

Ramu paints a menu board: "Masala chai ₹15. Elaichi chai ₹20. Add ginger +₹5." Customers don't need to know how the stove works; they just order from the board. When Ramu changes his recipe, the board stays the same, so nobody is confused. That board is an API: a stable contract that hides the kitchen.

Production API habits

Versioning

/v1/orders or a header. Never break existing clients; add fields, don't rename them.

Pagination

Offset (?page=5) is simple but slow and shifts when rows are added. Cursor (?after=ord_981) is stable and fast for feeds.

Idempotency keys

Client sends Idempotency-Key: uuid with a POST; the server stores the result and returns it again on retry. Stripe-style safe payments.

Consistent errors

Correct status codes and a body like {"code":"OUT_OF_STOCK","message":"…"}.

Real-time: how the server talks first

Lock it in

Nouns in the URL, verbs in the method.

REST for public and CRUD, GraphQL for flexible front ends, gRPC for fast internal calls. Real-time ladder: poll → long-poll → SSE → WebSocket. Always: version, paginate (cursor for feeds), and use idempotency keys on POSTs that move money.

Interview questions

How would you design pagination for an infinite-scroll feed?

Cursor-based: return items plus an opaque next_cursor (e.g. encoded last created_at + id). The next query is WHERE (created_at, id) < (cursor) ORDER BY created_at DESC, id DESC LIMIT 20, which uses an index and doesn't skip or repeat items when new posts arrive. Offset pagination gets slower with depth and shifts under inserts.

WebSocket at scale: what's hard?

Connections are long-lived and stateful, so each server holds many open sockets (memory, file descriptors); load balancers must support upgrades and long timeouts; to message a user you must know which server holds their socket (a connection registry in Redis, or pub/sub between servers); and reconnect storms after a deploy need jittered backoff.
