The toolbox: IDs, Bloom filters, geo, search and storage

Small, clever building blocks that show up again and again in design interviews. Know what each one is for and its one-line trade-off.

1. Unique IDs at scale: Snowflake

A single MySQL AUTO_INCREMENT breaks with many shards (two shards both produce id 1001). UUIDs are unique but 128 bits, random (bad for B-tree index locality) and not time-sortable. Twitter's Snowflake packs a time-sortable, unique 64-bit ID that any server can generate without coordination:

2. Bloom filter: "definitely not" or "probably yes"

A tiny bit array plus k hash functions that answers "have I seen this before?" using very little memory. False positives are possible; false negatives never happen.

Uses: skip a disk lookup for keys that don't exist (Cassandra, HBase), stop cache penetration, "username taken?" pre-checks, web crawler "already visited this URL?", Medium's "already recommended".

3. Geospatial: "find drivers within 2 km"

Geohash

Encode latitude/longitude into a string like tdr1y; nearby places share a prefix. Query your cell and its 8 neighbours. Redis GEOADD/GEOSEARCH uses this idea.

Quadtree

Recursively split the map into 4 squares until each has at most N points. Dense cities get small cells, empty areas big ones.

Uber H3 / Google S2

Hexagonal or spherical cell systems used in production ride-hailing and maps.

5. Keeping a cluster together

Heartbeats

Nodes send "I'm alive" every few seconds; missing several marks a node dead.

Gossip protocol

Each node tells a few random others what it knows; news spreads like rumours to all nodes in O(log N) rounds. Cassandra membership.

Leader election & consensus

Raft/Paxos let nodes agree on one leader and one log order, even if some fail (needs a majority). etcd, ZooKeeper, Kafka KRaft.

Distributed lock

Ensure only one worker runs a job: Redis SET key val NX PX 30000, or ZooKeeper/etcd leases. Use fencing tokens for safety.

6. Kinds of storage

TypeThink of it asExamplesUse for
Block storageA raw hard disk attached to one machineAWS EBS, SANDatabase data files, OS disks
File storageA shared folder with directoriesNFS, AWS EFSShared files between servers, legacy apps
Object storageAn infinite bucket of files, each with a key and metadata, via HTTPAWS S3, GCS, MinIOImages, videos, backups, data lakes; cheap and durable

Pattern you will draw constantly: store the file in object storage, store its URL/key in the database, serve it through a CDN. Upload directly from the client using a pre-signed URL so your servers don't carry the bytes.

7. Batch vs stream processing

Batch

Process a large, bounded dataset on a schedule (nightly reports, ML training). Hadoop MapReduce, Spark.

Stream

Process events continuously as they arrive (fraud detection, live dashboards). Kafka Streams, Flink, Spark Streaming.

Lock it in

Snowflake for IDs, Bloom for "no", Geohash for "near", Inverted index for "find".

Files go to object storage + CDN, with only the URL in the DB. Clusters agree through heartbeats, gossip and consensus (Raft).

Interview questions

Why can't a Bloom filter delete items, and what's the fix?

Clearing a bit might also clear it for other items that hashed to the same bit, causing false negatives. A counting Bloom filter stores small counters instead of bits, so deletes decrement them.

How do you serve "nearby restaurants" quickly?

Index restaurant locations by geohash (or quadtree). For a user, compute their geohash at a precision matching the search radius, fetch candidates in that cell plus its neighbours, then compute exact distances and rank. Restaurant locations rarely change, so the index can be cached heavily.
