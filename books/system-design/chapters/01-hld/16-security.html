Security: authentication, authorization, JWT and OAuth

Authentication asks "who are you?"; authorization asks "what are you allowed to do?" Every design should say how both happen.

At Ramu's chai stall

The flagship store's kitchen has a back door. Staff show an ID card to the guard to enter (authentication). Inside, a cook can use the stove but not open the cash safe; only the manager can (authorization, by role). Visitors get a wristband stamped with their access and an expiry time, so the guard doesn't phone the office every time; he just checks the stamp is genuine. That wristband is a JWT.

OAuth 2.0: "Login with Google", step by step

  1. RedirectYour app sends the user to Google's login page with your client ID and the permissions (scopes) you want.
  2. User consentsThe user logs in at Google (your app never sees the password) and approves.
  3. Authorization codeGoogle redirects back to your app with a short-lived code.
  4. ExchangeYour backend swaps the code (plus its client secret, or PKCE verifier for mobile/SPA) for an access token, and with OpenID Connect an ID token saying who the user is.
  5. UseYour app creates its own session or JWT for the user and may call Google APIs with the access token.

OAuth 2.0 is about authorization (granting access); OpenID Connect adds authentication (identity) on top.

Interview questions

How would you handle auth across 20 microservices?

Authenticate once at the edge (API gateway or an auth service via OAuth2/OIDC). Issue short-lived JWTs signed with a private key; services verify with the public key (JWKS) without calling the auth service. Pass the user identity downstream; use mTLS or a service mesh for service-to-service trust; enforce authorization (roles/scopes) in each service for its own resources.

How do you log out a user who has a JWT?

Keep access tokens short (5–15 minutes) and use refresh tokens stored server-side; logout revokes the refresh token. For immediate revocation, keep a small denylist of token IDs (jti) in Redis until they expire, or a per-user "tokens valid after" timestamp.
