Streams: pipelines, laziness and collectors

A stream is an assembly line: a source, some intermediate steps, and one terminal step. Nothing happens until the terminal step pulls items through, one at a time.

In Ramu's kitchen

Ramu's assembly line has stations: wash → peel → chop → fry → plate. Potatoes don't all get washed first and then all peeled; each potato goes down the whole line before the next. And if the order is "just 3 plates of fries", the line stops after the third plate: the rest of the sack is never touched. That's laziness and short-circuiting.

The collectors interviewers love

map vs flatMap

map: one in, one out

orders.map(Order::lines) gives a Stream<List<Line>>: a stream of lists.

flatMap: one in, many out, flattened

orders.flatMap(o -> o.lines().stream()) gives a Stream<Line>.

Optional: say "maybe empty" in the type

Parallel streams: careful

Common trap

.parallelStream() splits work over the shared ForkJoinPool.commonPool() (cores - 1 threads). It helps only for large, CPU-heavy, independent work on easily splittable sources (arrays, ArrayList). It hurts for small lists, LinkedList, I/O calls (one slow call blocks the shared pool for the whole JVM), and any code with shared mutable state. In a web server, it's usually the wrong tool.

Lock it in

Source, steps, one terminal. Nothing runs until the terminal.

Streams are lazy, single-use and don't change the source. Use toMap with a merge function, groupingBy for buckets, primitive streams for numbers.

Interview questions

Intermediate vs terminal operations?

Intermediate (filter, map, flatMap, sorted, distinct, limit, peek) return a stream and are lazy. Terminal (collect, forEach, reduce, count, findFirst, anyMatch, toList) trigger processing and end the stream. Short-circuiting ones (limit, findFirst, anyMatch) can stop early, even on infinite streams.

findFirst vs findAny?

findFirst returns the first element in encounter order. findAny may return any element, which lets parallel streams return whichever finishes first. In sequential streams they usually behave the same.

Find the second highest salary with streams.

emps.stream().map(Employee::salary).distinct().sorted(Comparator.reverseOrder()).skip(1).findFirst() returns an Optional. Mention that a SQL query with OFFSET 1 or DENSE_RANK is better when the data is in a database.

What does peek() do and when should you use it?

It runs an action on each element as it passes, without changing it. It's meant for debugging; don't rely on it for side effects because with laziness or short-circuiting it may not run for every element.
