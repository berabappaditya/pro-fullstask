Classes, objects, static and final

A class is a recipe card; an object is one dish made from it. Instance fields belong to each dish, static fields belong to the recipe card itself.

In Ramu's kitchen

The recipe card for Masala Chai says: water, milk, tea leaves, sugar level. Each cup made from it has its own sugar level (instance field). But "total cups sold today" is written once on the card itself, shared by all cups (static field). "Tea must be boiled at 100°C" is printed in ink and can never change (final).

The three meanings of final

final variable
Assign once

A final reference can't point elsewhere, but the object can still change: final List<String> l still allows l.add().

final method
Can't override

Subclasses must use it as is. Used for security-critical or template steps.

final class
Can't extend

String, Integer and records are final, so nobody can subclass and break their guarantees.

Static members are per class, instance members per object. Constructors chain with this(...)/super(...) as the first line. Statics first, parents first.

Interview questions

Can a static method access instance variables?

Not directly: there's no this in a static context. It can access them through an object reference passed in or created inside it.

Can we override a static method?

No. A static method with the same signature in a subclass hides the parent's; which one runs depends on the reference's declared type at compile time, not the object type. Overriding (runtime polymorphism) applies only to instance methods.

What's the difference between overloading and overriding?

Overloading: same method name, different parameter list, in the same class; resolved at compile time. Overriding: subclass provides a new body for an inherited instance method with the same signature; resolved at runtime by the object's actual type.
