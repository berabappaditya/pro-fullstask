Types, wrappers and casting

Java has 8 primitive types that hold values directly, and objects that are reached by reference. Wrappers like Integer bridge the two, with a few famous traps.

In Ramu's kitchen

Small things like a pinch of salt go straight into the pot (a primitive: the value itself). Bigger things come in a labelled jar on a shelf, and the recipe just says which jar (an object reference). Sometimes a machine only accepts jars, so Ramu puts his pinch of salt into a tiny jar first. That's boxing.

Autoboxing and its traps

Casting, overflow and money

Widening is automatic

int → long → float → double needs no cast and never loses magnitude.

Narrowing needs a cast

(int) 3.99 is 3 (truncates). (byte) 200 is -56 (wraps around).

Silent overflow

Integer.MAX_VALUE + 1 becomes negative. Use Math.addExact to throw instead, or long.

Floating point and money

0.1 + 0.2 == 0.30000000000000004. Use BigDecimal (from a String) for money.

Lock it in

"Be Smart In Life, For Decent Coffee Brews": byte, short, int, long, float, double, char, boolean.

Compare wrappers with equals, never ==. Never unbox something that can be null. BigDecimal for money, long for big counts.

Interview questions

Why does Integer a = 100, b = 100; a == b print true but 1000 prints false?

Integer.valueOf (used by autoboxing) caches values from -128 to 127, so both variables reference the same cached object. Outside that range new objects are created, and == compares references, not values.

Why can't you use primitives in generics like List<int>?

Generics work with object references (type erasure turns T into Object). Primitives aren't objects, so you use wrappers (List<Integer>) or primitive-specialised types like IntStream to avoid boxing.
