Executors and thread pools

Don't create a thread per task; hire a fixed team and put tasks on a queue. ThreadPoolExecutor's core → queue → max → reject order is a top SDE-2 question.

In Ramu's kitchen

The old way: every time an order arrives, hire a brand-new chef, they cook one dish, then fire them. Absurdly wasteful. A thread pool is the sane way: hire a fixed team of, say, 4 chefs once. Orders go onto a ticket rail (a queue). Whenever a chef is free, they grab the next ticket. On a busy night with 100 orders, still just 4 calm chefs working through the rail.

How many threads?

CPU-bound
≈ number of cores

Image resizing, encryption, parsing. More threads just add context switching. Runtime.getRuntime().availableProcessors().

I/O-bound
cores × (1 + wait / compute)

A task that waits 90 ms on a DB and computes 10 ms: 8 cores × 10 = ~80 threads. Or use virtual threads.

bounded by downstream
≤ connection pool

100 threads sharing a 10-connection DB pool means 90 threads waiting. Size them together.

Lock it in

Core, then queue, then max, then reject.

Always bounded queue, named threads, explicit rejection policy, and call shutdown(). Size CPU pools to cores and I/O pools to waiting time.

Interview questions

Explain the ThreadPoolExecutor parameters.

corePoolSize (threads kept alive), maximumPoolSize (upper limit), keepAliveTime (idle time before extra threads die), workQueue (where tasks wait), threadFactory (creates/names threads), and RejectedExecutionHandler (what to do when queue and max are full). New tasks go: start a core thread → else queue → else start a non-core thread up to max → else reject.

submit() vs execute()?

execute(Runnable) returns nothing; an exception goes to the thread's uncaught exception handler. submit() accepts Runnable or Callable and returns a Future; exceptions are stored inside it and rethrown (wrapped in ExecutionException) only when you call get().

shutdown() vs shutdownNow()?

shutdown stops accepting new tasks but finishes queued ones. shutdownNow also interrupts running tasks and returns the list of tasks that never started. Follow either with awaitTermination.
