Garbage collection: who cleans the heap

The GC finds objects no live reference can reach and frees their memory. Most objects die young, so the heap is split into a young area cleaned often and an old area cleaned rarely.

In Ramu's kitchen

The cleaner doesn't ask "is this plate dirty?". He starts from what chefs are currently holding or pointing at and marks everything reachable from there. Anything unmarked is cleared. He cleans the prep counter (young generation) every few minutes because most things there are scraps used once. Plates that survive several cleanings get moved to the long-term shelf (old generation), which he cleans only occasionally because it's slow.

Interview questions

Can you force garbage collection?

System.gc() is only a request; the JVM may ignore it (and -XX:+DisableExplicitGC disables it). Calling it in application code is almost always a mistake.

What is a stop-the-world pause?

A phase where all application threads are paused so the GC can work safely (at safepoints). Modern collectors (G1, ZGC, Shenandoah) do most of their marking and compaction concurrently to keep these pauses short.

Strong, soft, weak and phantom references?

Strong: normal; never collected while reachable. Soft: collected only when memory is low (memory-sensitive caches). Weak: collected at the next GC once only weakly reachable (WeakHashMap keys, canonical maps). Phantom: used with a ReferenceQueue for post-mortem cleanup (Cleaner).

What is finalize() and why avoid it?

A method the GC might call before reclaiming an object. It's unpredictable, slow, can resurrect objects, and is deprecated for removal. Use try-with-resources or java.lang.ref.Cleaner.
