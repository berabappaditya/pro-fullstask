Common traps

Mixing user text into instructions without delimiters (invites prompt injection, {{n:ch-mcp-security}}). Asking for JSON without validation (always parse, validate, retry on failure). Huge prompts full of irrelevant context (worse answers, more cost). Changing prompts without an evaluation set ({{n:ch-rag-eval}}): you won't know what you broke.

Lock it in

A job card for a brilliant colleague with no context.

Role, task, context, rules, output format, examples. Delimit data. Structured output for code. Version prompts and test them like code.

Interview questions

How do you get reliable JSON from an LLM?

Use the provider's structured-output / JSON-schema mode or tool-calling with a schema; keep the schema simple with enums; low temperature; validate against the schema in code (Bean Validation on the record) and retry with the error message on failure; keep a fallback path (human review) for repeated failures.

Zero-shot vs few-shot vs chain-of-thought?

Zero-shot: instructions only. Few-shot: plus a handful of input→output examples to pin down format and edge cases. Chain-of-thought: ask the model to reason step by step (or use a reasoning model) before the final answer, improving multi-step problems at the cost of tokens and latency.
