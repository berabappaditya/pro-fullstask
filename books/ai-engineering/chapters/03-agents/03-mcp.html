MCP: one standard socket between AI apps and everything else

The Model Context Protocol is an open JSON-RPC protocol through which AI applications (clients) discover and use tools, resources and prompts exposed by servers. Write a server once; every MCP-capable app can use it.

Ramu's assistant

Before, every new appliance needed a custom-wired plug for every assistant: GitHub for Claude, GitHub for the IDE, GitHub for the chatbot (N × M integrations). MCP is a standard socket: each appliance gets one MCP plug (server), each assistant one socket (client), and anything plugs into anything (N + M).

Interview questions

What problem does MCP solve and how is it different from function calling?

It standardises how AI applications connect to external tools and data so integrations are built once and reused across hosts (N+M instead of N×M). Function calling is the model capability of emitting structured tool calls; MCP is the protocol by which the host discovers and invokes tools hosted elsewhere. A host typically turns MCP tool listings into function definitions for its model.

Why did MCP become stateless in 2026?

Sessions made remote servers hard to scale and deploy behind load balancers and serverless platforms (sticky sessions, session stores, resumable streams). Making each request self-contained (version and capabilities in _meta, no session id) lets servers be ordinary stateless HTTP services, cacheable and horizontally scalable, while MRTR replaces server-initiated requests that needed a persistent bidirectional channel.
