Agents: models that loop toward a goal

An agent is an LLM using tools in a loop: think, act, observe, repeat, until the goal is reached or a limit is hit. Start with simple workflows; add autonomy only where it pays.

Ramu's assistant

"Find out why Pune's orders dropped this week and draft a note to the manager." The assistant plans, checks the sales dashboard, sees deliveries were late, checks the delivery partner's status page, finds an outage, and drafts the note. Each step depends on what he just learned. Ramu sets rules: at most 10 steps, no emails sent without his OK.

Keep it safe

Step and token budgets, timeouts, allow-listed tools, least-privilege credentials, human approval for side effects, sandboxed code execution, output validation.

multi-agent
Specialists

Several agents with narrow roles (researcher, coder, reviewer) coordinate; agent-to-agent protocols such as A2A standardise how they talk. More power, more cost and debugging effort.

Why agents fail

Errors compound over steps (95% per step ≈ 60% over 10 steps), loops that never finish, tool misuse, context filling with noise, cost blow-ups, and prompt injection from tool outputs. Prefer the simplest workflow that works, and evaluate end-to-end task success, not single replies.

Lock it in

Plan, act, look, repeat, within a budget, with permission for anything irreversible.

Agent = LLM + tools + loop + memory + guardrails. Workflows first, autonomy when needed. Trace every step.

Interview questions

Agent vs workflow?

A workflow follows code-defined steps where LLMs fill in specific parts: predictable, testable, cheaper. An agent lets the model choose the next step and tools dynamically: flexible for open-ended tasks but less predictable. Use workflows by default; agents where the path can't be known in advance.

How do you make an agent production-safe?

Narrow, well-described tools with least-privilege credentials scoped to the end user; validation and authorisation inside each tool; human approval for irreversible actions; step/token/time budgets; sandboxing for code execution; treat tool outputs as untrusted (prompt injection); full tracing; evaluation on realistic tasks; kill switches.
