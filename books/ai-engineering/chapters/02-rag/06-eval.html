Evaluating RAG and LLM applications

You can't improve what you don't measure. Build a test set of real questions, measure retrieval and generation separately, and run it on every prompt, model or chunking change.

Ramu's assistant

Ramu keeps a stack of 200 real customer questions with the right answers and the handbook pages that contain them. Every time he changes how the assistant works, he runs the whole stack and checks: did it find the right pages? Did it stick to them? Did it actually answer? A senior manager grades the tricky ones (LLM-as-judge, with spot checks by humans).

LLM-as-judge caveats

Judges have biases (prefer longer answers, their own model family, the first option). Use clear rubrics, binary or small-scale scores, a different/stronger judge model, and calibrate against human labels on a sample.

Interview questions

How would you evaluate a RAG system before launch?

Build a golden set (real or realistic questions, expected answers, relevant docs, including unanswerable and adversarial ones). Measure retrieval recall@k/MRR, then faithfulness and correctness via a calibrated LLM judge plus human review of a sample, plus format/citation checks and latency/cost. Compare variants (chunking, k, reranker, prompt, model) offline; launch to a small group with feedback; keep monitoring and add failures to the set.
