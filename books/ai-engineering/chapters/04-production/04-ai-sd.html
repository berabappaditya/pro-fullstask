AI system design interview: an AI support assistant over company knowledge

Same framework as any system design: requirements, numbers, high-level design, deep dives, trade-offs, plus the AI-specific parts: retrieval quality, evaluation, safety and cost.

The question

"Design an AI assistant for Ramu Chai's 2,000 support agents and customers that answers questions from policies, FAQs and past tickets, can look up order status, and hands over to a human when needed."

  1. RequirementsFunctional: answer with citations, multi-turn chat, order lookup tool, human handoff, multilingual (English/Hindi/Hinglish), admin can upload docs. Non-functional: p95 first token < 2 s, answers grounded (no invented policies), per-tenant data isolation, PII protection, cost ceiling per conversation, 99.9% availability (degrade to search if the LLM is down).
  2. Numbers50k conversations/day × 4 turns = 200k LLM calls/day ≈ 2.3/s average, ~20/s peak. 30k documents → ~600k chunks × 1,536 dims ≈ 3.7 GB of vectors: fits pgvector on one beefy instance with replicas. Tokens: ~3k in / 300 out per call → budget with prompt caching ({{n:ch-sampling}}).
  3. High-level designSee the figure: ingestion pipeline (async), chat service (stateless, Spring AI), retrieval (hybrid + rerank), LLM gateway (routing, fallback, quotas), tools via MCP, conversation store, evaluation and observability.
  4. Deep divesRetrieval quality (chunking, hybrid, rerank, metadata filters for tenant/ACL), groundedness (prompt rules, citations verified, "I don't know"), safety (injection from ticket text, PII redaction, tool permissions per user), cost and latency (caching, routing, streaming), evaluation (golden set in CI, LLM judge + human review, online feedback).
  5. Trade-offspgvector vs dedicated vector DB, hosted vs self-hosted model (data residency), long context vs RAG, agentic multi-step vs fixed workflow, freshness vs ingestion cost.
What makes this an SDE-2 answer

You quantify (calls/s, tokens, vector size, cost), you separate retrieval from generation and say how you'll measure each, you put security in code (tenant filters, per-user tool tokens, injection handling) rather than in the prompt, you design for provider failure and cost, and you describe how the system improves after launch (feedback → evaluation set → changes behind CI).

Interview questions

How do you keep answers fresh when policies change?

Event-driven ingestion: document upload/update events trigger re-chunking and re-embedding of that document only (delete old chunks by doc id, insert new), with version and effective-date metadata; filter out expired versions at query time; invalidate semantic-cache entries citing that document; monitor ingestion lag.

How do you guarantee tenant isolation in a multi-tenant RAG system?

Every chunk carries tenant (and ACL) metadata; the retrieval service applies the filter from the authenticated identity, never from model output; optionally separate indexes/schemas per large tenant; tools receive per-user tokens; caches are keyed by tenant; tests assert cross-tenant queries return nothing.
