Calling other services: RestClient and HTTP interfaces

RestClient is the modern synchronous client; @HttpExchange interfaces let Spring generate the client for you. Always set timeouts.

In the franchise

The branch orders milk from a dairy by phone. Old way: dial, read out every detail yourself (RestTemplate). New way: a pre-printed order pad with the dairy's fields; fill in quantity and the system places the call (HTTP interface). And never wait on hold forever: hang up after 2 seconds (timeouts).

Production checklist

Timeouts (connect + read) on every client, retries only for idempotent calls with backoff and jitter, a circuit breaker (Resilience4j, or Spring Framework 7's built-in @Retryable/@ConcurrencyLimit resilience annotations), and propagate the trace id. Patterns are explained in {{xref:system-design/ch-reliability}}.

Interview questions

RestTemplate vs WebClient vs RestClient?

RestTemplate: older synchronous API, now in maintenance. WebClient: reactive and non-blocking, returns Mono/Flux, best in WebFlux. RestClient: synchronous with a fluent API like WebClient but no reactive dependency; the recommended choice for Spring MVC apps (and fits virtual threads well).

How do services call each other in a microservice architecture?

Synchronously over HTTP/gRPC (RestClient, HTTP interfaces, Feign) when the caller needs an immediate answer, or asynchronously via events on Kafka/RabbitMQ for decoupling and resilience. Add service discovery or Kubernetes DNS, timeouts, retries and circuit breakers.
