Common trap

Validation annotations alone do nothing: without @Valid (or @Validated on the class for method parameters) they're never checked. And validate DTOs at the API boundary; business rules that need the database (email already exists) belong in the service.

Interview questions

@Valid vs @Validated?

@Valid is the standard Jakarta annotation: triggers validation of an argument and cascades into nested objects. @Validated is Spring's: on a class it enables method-level validation of simple parameters via a proxy, and it supports validation groups.

What are validation groups?

Marker interfaces assigned to constraints so different rules apply in different contexts, e.g. id must be null on Create but not null on Update: @Validated(OnCreate.class).
