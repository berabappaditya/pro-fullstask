Architecture: the life of an HTTP request

Filters → DispatcherServlet → handler mapping → controller → service → repository → database, and back through message converters as JSON. Each layer has one job.

In the franchise

A customer walks in. The guard checks them (filters). The host at the front desk reads their order and sends them to the right counter (DispatcherServlet). The counter clerk takes the order (controller), the chef decides how to make it (service), the storekeeper fetches ingredients (repository) from the storeroom (database). The finished cup goes back along the same path.

Interview questions

What is the DispatcherServlet and why is it called the front controller?

It's the single servlet that receives every request to Spring MVC. It looks up the handler through HandlerMappings, invokes it through a HandlerAdapter (resolving arguments), handles exceptions via HandlerExceptionResolvers, and writes the result with message converters or view resolvers. One entry point that delegates is the Front Controller pattern.

Filter vs HandlerInterceptor?

Filters are servlet-level and run before the DispatcherServlet for every request (security, CORS, compression). Interceptors are Spring MVC-level, run around controller methods, and know which handler was chosen (auditing, per-endpoint timing, locale).
