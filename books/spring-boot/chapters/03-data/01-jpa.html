JPA and Hibernate: entities, relationships and the N+1 problem

JPA is the specification, Hibernate the implementation, Spring Data the convenience layer. Map classes to tables, keep associations LAZY, and fetch what you need explicitly.

In the franchise

The storekeeper keeps a working copy of every ledger page he's opened today (the persistence context). Change a number on his copy and he updates the real ledger at closing time (dirty checking on commit). If you ask for 50 customers and then, one by one, "what did this customer order?", he walks to the storeroom 51 times (N+1). Smart: "give me the 50 customers with their orders" in one trip (JOIN FETCH).

The N+1 problem

Two traps

JOIN FETCH of a collection + pagination: Hibernate paginates in memory (warning HHH90003004). Page the parent ids first, then fetch. LazyInitializationException: touching a lazy field after the transaction closed. Fix by fetching what you need inside the service, not by turning on EAGER or open-in-view.

Lock it in

One trip with everything, not fifty-one trips.

JPA = spec, Hibernate = implementation. LAZY everywhere, fetch explicitly (JOIN FETCH, @EntityGraph, DTO projections). Owning side has the FK; mappedBy marks the inverse. Prod: ddl-auto none/validate.

Interview questions

What is the N+1 problem and how do you detect it?

One query loads N parents, then accessing a lazy association triggers one query per parent. Detect with SQL logging (spring.jpa.show-sql or a datasource proxy), Hibernate statistics, APM traces showing repeated identical queries, or tests asserting query counts. Fix with JOIN FETCH, @EntityGraph, batch fetching or DTO projections.

What is the first-level cache?

The persistence context (EntityManager/Session) caches entities by id for the duration of the transaction, so repeated find calls return the same instance without a query and changes are tracked for dirty checking. A second-level cache (Ehcache, Caffeine via JCache) is optional and shared across sessions.

What does cascade = ALL with orphanRemoval do?

Cascade propagates persist/merge/remove from parent to children. orphanRemoval deletes a child row when it's removed from the parent's collection. Use only for true composition (order lines belong to one order), never on @ManyToOne.
