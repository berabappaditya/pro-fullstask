Spring Security: the filter chain, JWT and method security

Every request passes through a chain of security filters before it reaches your controller. Authentication = who you are; authorization = what you may do.

In the franchise

At the door, the guard checks your membership card (authentication). A signed wristband from the front desk lets you walk around without showing ID again (a JWT). Some rooms need a staff badge (role ADMIN) and the kitchen checks it again at the kitchen door (method security). The guard never keeps a list of who's inside: the wristband itself proves it (stateless).

Common traps

Putting secrets in the JWT payload (it's only Base64, anyone can read it). Long-lived access tokens with no revocation. Accepting alg: none or not checking expiry (use the library, don't parse by hand). Storing passwords with MD5/SHA-256 instead of a slow, salted hash (BCrypt, Argon2). Forgetting that role checks need the ROLE_ prefix with hasRole.

Interview questions

Explain the Spring Security filter chain.

Spring registers one servlet filter (DelegatingFilterProxy → FilterChainProxy) that delegates to the first matching SecurityFilterChain bean, an ordered list of filters: CORS, CSRF, authentication filters (form, basic, bearer token), exception translation (turns AuthenticationException into 401 and AccessDeniedException into 403), and the AuthorizationFilter that applies the URL rules. The authenticated user lives in the SecurityContextHolder for the request.

How do you implement JWT authentication?

Login endpoint authenticates via AuthenticationManager and issues a signed short-lived access token (and refresh token). Each request's Bearer token is validated by the resource server support (signature, expiry, issuer, audience) which builds the Authentication with authorities from claims. Stateless session policy, HTTPS, key rotation, refresh token rotation and revocation strategy. Prefer an identity provider (Keycloak, Cognito, Auth0) for issuing tokens.

Why BCrypt?

It's deliberately slow with a configurable cost factor and a per-password salt, so brute-forcing leaked hashes is expensive and rainbow tables are useless. The delegating encoder stores the algorithm id ({bcrypt}…) so you can upgrade to Argon2 later.
