Interview questions

A Linux server is slow. Walk through your first five minutes.

uptime (load vs cores), top/htop (which process, user vs I/O wait), free -h (memory, swap), df -h (full disks), iostat/vmstat (disk and CPU saturation), the service's logs (journalctl), network checks (ss, curl to dependencies). For Java, thread dumps and GC stats. Compare with metrics history to see when it started.

df shows the disk full but du can't find the big files. Why?

A process still has a deleted file open (often a log deleted instead of rotated); the space isn't freed until the file descriptor closes. Find it with lsof +L1 and restart that process or truncate via /proc/PID/fd. Use logrotate with copytruncate or proper reopen signals.

SIGTERM vs SIGKILL?

SIGTERM (15) asks the process to exit; it can catch it and clean up (Spring Boot graceful shutdown finishes in-flight requests). SIGKILL (9) can't be caught: the kernel kills it immediately. Docker and Kubernetes send SIGTERM, wait a grace period, then SIGKILL.
