CI/CD and deployment strategies

CI: every commit is built and tested automatically. CD: every green build can be released safely, with a strategy that limits blast radius and allows instant rollback.

In the food court

A new recipe travels on a conveyor belt: tasted by the quality team (tests), sealed (image), first served at one counter to a few customers (canary), watched for complaints (metrics), then rolled out to every counter. If customers frown, the belt reverses (rollback).

Interview questions

Continuous delivery vs continuous deployment?

Continuous delivery: every change is automatically built, tested and ready to release; production release is a button press (manual approval). Continuous deployment: every change that passes the pipeline goes to production automatically.

How do you deploy a database schema change without downtime?

Expand–migrate–contract: first deploy a backward-compatible change (add nullable column/new table) that both old and new app versions tolerate; deploy the app that writes both/reads new; backfill data; once no old version runs, remove the old column in a later release. Never rename or drop in the same release as the code change.

What is GitOps?

The desired state of every environment lives in Git (Kubernetes manifests, Helm values). An agent in the cluster (Argo CD, Flux) continuously syncs the cluster to Git. Deploys and rollbacks are pull requests and reverts, with history and review built in; the CI system needs no cluster credentials.
