Storage and managed databases

Object storage for files, block storage for a VM's disk, managed databases for structured data. Let the cloud run backups, patching and failover.

Managed relational databases: what you get

HA
Multi-AZ standby

Synchronous copy in another AZ with automatic failover (~1–2 min; Aurora faster). Not for reads.

scale reads
Read replicas

Asynchronous copies for read traffic, reports, cross-region DR. Watch replication lag.

recovery
Automated backups + PITR

Restore to any second within the retention window (e.g. 7–35 days). Test restores regularly.

ops
Patching, monitoring, storage autoscaling

Maintenance windows, Performance Insights / Query Insights, encryption with KMS.

connections
RDS Proxy / pooling

Shares DB connections among many app instances or Lambdas.

Cold store, drawer, accounts office.

Interview questions

Multi-AZ vs read replica?

Multi-AZ is a synchronous standby for automatic failover; it doesn't serve reads (except in some newer cluster deployments). A read replica is an asynchronous copy that serves reads and can be promoted manually; it may lag. Use both: Multi-AZ for availability, replicas for read scaling.

How do you let users upload large files?

The API authorises the user and returns a short-lived presigned URL (or POST policy); the client uploads directly to S3/GCS, using multipart upload for large files. An S3 event triggers processing (virus scan, thumbnails) asynchronously. The bucket stays private and blocks public access.
